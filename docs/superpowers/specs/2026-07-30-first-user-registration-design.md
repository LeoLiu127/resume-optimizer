# 首位用户免邀请码注册设计

## 目标

消除全新数据库的首次注册死锁：数据库中没有任何用户时，第一位注册者不需要邀请码，设置昵称和至少 8 位密码后直接成为管理员。

## 规则

- 免邀请码仅适用于服务端数据库中用户数量为 `0` 的注册请求。
- 第一位用户注册成功后，第二位及以后用户继续按照现有邀请模式强制校验邀请码。
- 登录流程不变：只有已注册账号才能使用昵称和密码登录。
- 首次注册界面隐藏邀请码输入框，并显示“首位用户免邀请码，将自动成为管理员”。
- 已有用户时，注册界面继续显示邀请码输入框及现有邀请说明。
- 服务端数据库状态是最终依据；前端 `bootstrap.hasUsers` 只负责界面呈现。

## 快速补丁边界

- 不增加数据库迁移。
- 不重构认证架构。
- 不增加首位注册的并发事务锁；这是用户明确选择的快速补丁范围。
- 不修改密码规则、会话规则、管理员权限或邀请码管理功能。

## 错误处理

- 数据库无用户且邀请码为空：允许注册。
- 数据库已有用户且邀请码为空：返回 `400` 和“请提供邀请码”。
- 数据库已有用户且邀请码无效、撤销、过期或用完：保持现有错误。
- 前端尚未取得 bootstrap 结果时保持邀请码必填，避免因加载失败放宽注册。

## 验收

- 首位用户可以在没有邀请码数据的全新数据库中注册并获得 `admin` 角色。
- 第二位用户不提供邀请码时注册失败。
- 第一位用户界面不显示邀请码字段。
- 已有用户界面显示邀请码字段并要求填写。
- 现有全量服务端测试和前端生产构建通过。
